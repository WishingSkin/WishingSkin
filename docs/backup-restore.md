# 本机备份与隔离恢复

备份命令面向停写后的 WishingSkin，不读取或执行 SQL dump，也不能替代 BS 迁移快照。当前格式为 1，要求数据库 schema 与当前程序完全一致（当前为 10）；没有自动跨版本恢复或 schema 降级。schema 9 或更早的旧备份需要先用匹配的旧程序恢复到独立目标，再用新程序执行 `migrate`；不能直接交给 schema 10 程序恢复。

## 保存范围

目录包含完成清单 `manifest.json`、13 张业务表的 JSONL 和 `textures/`。账号及密码哈希/盐、角色 UUID 与绑定、材质归属/描述/公开及下架状态、衣柜别名、账号验证状态、站点设置与签名私钥、迁移状态、管理审计、举报、余额和积分流水均保留；另含独立的 `legacy_reports` 旧举报历史及其孤立编号、原时间文本和长正文，以及 `user_profiles` 中的头像来源、上传头像和跟随角色设置。昵称保存在账号表中，Logo、主题、公告格式与官方模块配置随站点设置保留。整数按十进制字符串保存，避免大余额或历史编号精度损失；NULL 保持 NULL。

网页会话、游戏令牌、加入记录、邮件验证/找回链接及邀请码不进入备份，恢复后全部无效。用户重新登录；尚未完成验证的账号需要重发验证邮件。原库中的这些凭据不会因导出而被撤销。迁移 `pending` 阻止备份，`partial` 原样保留，恢复不把部分迁移标为完成。

每张表记录行数及 SHA-256，每份数据库引用的材质记录大小及独立 SHA-256，包括下架文件。孤立文件、上传临时文件及旧迁移目录清单不复制。原图片内容和存储 hash 不改变；SHA-256 用于检查副本，与自定义旧 hash 的计算方式无关。

`WS_PUBLIC_URL`、数据库连接和代理设置来自环境，操作人员需另外保存并配置。SMTP / Turnstile 的环境配置只作为初始值；通过后台保存后，数据库中的 `service_config` 密文优先并随业务备份原样保留，恢复后需要原设置密钥才能使用。密钥默认位于 `<WS_TEXTURE_DIR>/.settings.key`，可通过 `WS_SETTINGS_KEY_FILE` 指定独立路径；**业务备份不包含此密钥文件，必须单独安全备份并限制访问**。不要把服务密码、Secret 或密钥写进核对报告。

恢复完成后、启动服务前，将对应的原密钥安全放到目标配置路径。存在服务配置密文但缺少密钥时，程序拒绝启动；错误的 32 字节密钥无法解密配置，`/readyz` 和相关配置接口返回 503，不会静默回退到环境配置。丢失密钥意味着无法恢复这些服务秘密。数据库设置表还包含签名私钥，整个备份属于敏感数据，必须放入受控目录；备份格式不加密，摘要也不提供来源认证。Windows 的 `0600` 不能代替 NTFS ACL。

## 操作顺序

先停止本站所有服务实例、迁移器及其他业务写入；`--offline` 是操作人员的停写确认，程序不会远程协调停机。数据库使用只读、可重复读事务导出，文件复制期间仍须保持停写和目录不变。目标父目录必须存在，备份目录必须是全新路径，且与源材质目录互不包含。

```powershell
# 已配置原站 WS_DATABASE_DRIVER / WS_DATABASE_DSN / WS_TEXTURE_DIR，并停止所有写入。
./bin/wishingskin.exe backup --offline --directory backups/site-20261023

# 配置另一套空数据库；材质目录选择尚不存在、独立的新路径。
$env:WS_DATABASE_DSN='connection-to-isolated-empty-target'
$env:WS_TEXTURE_DIR='data/restored-textures'
./bin/wishingskin.exe migrate
./bin/wishingskin.exe restore --offline --directory backups/site-20261023
```

`backup` / `restore` 不自动升级数据库；先用对应版本的 `migrate` 初始化空目标。已有账号、会话、邀请码、业务记录或非默认设置均阻止恢复；仅允许初始化自带的角色上限 1、邮箱验证注册（或旧版默认关闭注册）和关闭全零积分规则。恢复不覆盖任何已有材质目录，即使该目录为空。源备份与目标材质目录必须独立。

恢复先检查清单版本、允许的表清单、行结构、行数、摘要及材质库存，然后复制文件、在一个数据库事务中写入全部业务表。文件名只接受受限 hash，表与列由程序固定，不执行清单中的 SQL。复制及入库时再次校验摘要，发生变更或 SQL 错误会回滚业务事务。

## 中断与切换

完成清单最后写入，缺少清单或清单损坏的目录不能恢复。失败导出会保留已经创建的目录，排查后选择新路径重新导出。恢复目录先写 `.restore-incomplete.json`；确认数据库提交后改名为 `.restore-complete.json`。SQL 失败时文件保留供排查，不自动删除或复用目录。重试使用新的空目录，数据库也应确认仍为空；若提交结果不确定或完成标记失败，先核对持久数据库状态，不要直接重试或清除标记。

单个 JSONL 行上限 64 MiB（含编码开销，达到该值即拒绝），清单上限 32 MiB；超过限制会停止，不截断历史。BS 快照整体仍限 64 MiB。工具逐行处理业务数据、逐个复制文件，但清单及材质索引随文件数增长。17 MiB 单条历史正文的跨库恢复已纳入回归；这不等于大正文资源容量验收。当前未演练断电、存储设备损坏或外部进程篡改；文件同步与事务成功不能代替这些演练。

验证完成前不要把隔离目标接入生产。切换后的新数据不在旧备份中；回退必须另行安排停写和新增数据处理，不能把恢复旧快照称为无损回滚。
